# Persistent HCIE chunks
The operator-owned revision database stages deterministic chunk descriptors in SQLite WAL with full synchronous commits. Only a fully verified source scan and matching manifest seal makes descriptors available to bounded cursor readers. Interrupted scans retain provisional descriptors and replay from the beginning, checking existing rows rather than duplicating them. Empty sources are explicitly sealed. Conflicting revision, source identity, chunk policy, and missing or changed records fail closed.

This is a single-supervisor local persistence layer, not a distributed scheduler or a guarantee of arbitrary repository size. Replay rereads the source; it is not an offset-only resume. The database must be protected from untrusted writers; per-page validation is not an independent full manifest authentication. No customer source is edited. No paid infrastructure or engine changes.
